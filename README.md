# pocketbase-react-template

A reusable starting point for PocketBase + React projects: a single Go binary
(PocketBase) that embeds a built React/Vite SPA and serves both the API and
the static frontend from one process. Docker is used for deploy only — local
dev runs the Go binary and the Vite dev server directly.

Always included: PocketBase (Go backend + JS SDK), TanStack Router (file-based)
+ TanStack Query, Tailwind CSS + shadcn/ui, with a landing page, a login page,
and a protected `/dashboard` route wired up as a starting point.

Selectable at scaffold time: Zod, Vitest, Storybook.

## Usage

```sh
curl -fsSL https://github.com/<GH_OWNER>/pocketbase-react-template/raw/main/setup.sh | bash
```

Run it in an empty directory. It'll prompt for a project name and which
optional pieces to include (or pass flags for non-interactive use):

```sh
curl -fsSL https://github.com/<GH_OWNER>/pocketbase-react-template/raw/main/setup.sh | \
  bash -s -- --name my-app --dir ./my-app --no-storybook -y
```

Run `setup.sh --help` (or pipe `-- --help`) for all flags.

## After scaffolding

```sh
cd my-app
mise install              # Go + Node, pinned versions
cd frontend && npm install && cd ..

make dev                  # PocketBase on :8090 (run in one terminal)
cd frontend && npm run dev   # Vite on :3000, proxies /api to :8090 (another terminal)
```

Open `http://localhost:3000`. On first run, create a PocketBase superuser at
`http://localhost:8090/_/` to access the admin UI, and a regular `users`
record (or sign-up flow of your own) to test the login page.

## Project layout

- `cmd/start/` — Go entrypoint.
- `internal/handlers/`, `internal/hooks/`, `internal/server/` — API routes,
  PocketBase hooks, and route registration.
- `migrations/` — PocketBase Go migrations (starts empty; the auth demo uses
  PocketBase's built-in `users` collection).
- `frontend/` — generated by `tanstack create` + this template's overlay.
  See `frontend/README.md` for frontend-specific notes.
- `Dockerfile`, `docker-compose.yml` — production packaging. Not needed for
  local dev.

## Building for production

```sh
make build        # builds frontend, then the Go binary with it embedded
# or:
docker build -t my-app .
docker compose up -d
```

## Auth pattern

Each redirect decision is owned by exactly one route, to avoid double/racing
redirects:

- `frontend/src/routes/index.tsx` — public landing page, links to `/login` or
  `/dashboard` depending on auth state. Never redirects on its own.
- `frontend/src/routes/login.tsx` — owns "already logged in → skip login",
  via its own `beforeLoad`.
- `frontend/src/routes/_auth/route.tsx` — pathless layout route, owns "not
  logged in → redirect to `/login`" for everything nested under it.

## Known rough edges

- `npm run lint` may flag two `import/consistent-type-specifier-style`
  warnings inside shadcn-generated files under `src/components/ui/`. These
  come from upstream shadcn's registry output vs. this template's ESLint
  config and aren't introduced by the overlay; they're regenerated as-is if
  you re-run `npx shadcn@latest add`.
- Storybook's `addon-vitest` (browser-based component testing) is
  intentionally stripped during setup — it currently requires Vitest ^4,
  which conflicts with the pinned Vitest 5.x used by the `--with-vitest`
  option. Storybook itself (`npm run storybook`) still works fine.
